========================================
일자리 비교·선택 도우미 앱
기획 및 개발 계획서
========================================
작성일: 2026년 9월 10일


----------------------------------------
1. 왜 만드는가 (문제 정의)
----------------------------------------

구직자는 여러 개의 채용공고를 놓고 비교할 때,
각자 중요하게 여기는 기준이 서로 다르다.

  - 어떤 사람은 "돈이 최우선"
  - 어떤 사람은 "아이 등원/하원 시간"이 최우선
  - 어떤 사람은 "몸이 편한 일"이 최우선

그런데 지금까지 사람들은 이걸
머릿속으로 대충 비교하거나, 엑셀을 켜서 일일이 계산한다.

[이 앱의 역할]
"당신에게 중요한 순서대로 고르면,
 공고들을 자동으로 채점해서 순위를 매겨준다."

즉, 공고를 '검색'해주는 앱이 아니라
공고를 '선택'하게 도와주는 앱이다.


----------------------------------------
2. 기존 서비스와 무엇이 다른가
----------------------------------------

알바몬, 잡코리아, 당근알바, 사람인 등은
"공고를 찾는 것"에는 강하다.

하지만 찾고 난 다음,
- 이 중에 나한테 뭐가 제일 나은지
- 겉으로 월급이 높아 보이는 곳이 진짜 나은 건지
이걸 판단해주는 기능은 없다.

우리 앱의 포지션:
  채용 검색 엔진 (X)
  의사결정 보조 도구 (O)

핵심 무기 3가지
  (1) 겉급여가 아닌 '실제 환산시급'을 자동 계산
  (2) 사용자마다 다른 우선순위를 직접 정할 수 있음
  (3) 결과를 카드/PDF로 저장·공유 가능


----------------------------------------
3. 누가 쓰는가 (타겟 사용자)
----------------------------------------

유형 A. 어린 자녀가 있는 부모
  → 출근시간, 퇴근시간, 가족과 겹치는 시간이 중요

유형 B. 사회초년생 / 1인 가구
  → 시급, 월급, 워라밸이 중요

유형 C. 경력단절 후 재취업자
  → 초보 가능 여부, 근무 강도, 4대보험이 중요

유형 D. 예비 창업자
  → 업종 노하우 습득 가능성, 창업 진입비용이 중요

유형 E. 투잡 / 부업 희망자
  → 근무 요일, 시간 유연성이 중요

※ 중요:
  이 유형들을 '템플릿 버튼'으로 미리 만들어두면
  사용자가 복잡한 설정 없이 버튼 하나로 시작할 수 있다.
  (예: "육아 병행형", "고수익 우선형", "창업 준비형")


----------------------------------------
4. 어떻게 동작하는가 (핵심 4단계)
----------------------------------------

[1단계] 공고 입력
  방법 1: 공고 텍스트 복사해서 붙여넣기 (여러 개 한번에)
  방법 2: 공고 캡처 이미지 업로드 → 자동 인식
  방법 3: 직접 항목별로 입력

  자동으로 추출할 항목:
    업체명 / 출근시간 / 퇴근시간 / 근무요일 /
    월급 또는 시급 / 휴게시간 / 업종 / 지역 /
    4대보험 여부 / 초보가능 여부

[2단계] 내 우선순위 정하기  ★ 핵심 차별점 ★
  - 여러 기준 중에서 내가 볼 것만 골라서 켠다
  - 고른 기준끼리 순서를 드래그로 정한다
  - 또는 슬라이더로 중요도(%)를 직접 조절한다

  선택 가능한 기준 목록(예시):
    □ 출근 가능 시간대 (예: 9시 이후만)
    □ 퇴근 가능 시간대
    □ 실제 환산시급
    □ 월급 총액
    □ 주5일 / 주6일 여부
    □ 가족(또는 개인) 여가시간
    □ 통근 거리·시간
    □ 창업 연계 가능성
    □ 초보 가능 여부
    □ 4대보험 가입 여부
    □ 근무 강도 (서서 하는 일 / 체력 소모)
    □ 야간근무 여부

[3단계] 자동 채점 및 순위 산출
  - 앱이 각 기준별 실제값을 계산
    · 환산시급 = 월급 ÷ (주당근무시간 × 4.345)
    · 가족시간 = 가족 귀가시간과 내 비근무시간의 겹침
    · 실수령 추정액 = 세전급여 - 4대보험/세금 추정
  - 사용자가 정한 우선순위대로 가중치 반영
  - 종합 점수 계산 → 1위부터 순위 나열

[4단계] 결과 확인 및 공유
  - 카드형 순위표로 결과 표시
  - 각 항목의 '실제 값'도 함께 표시 (점수만 보여주면 신뢰가 안 감)
  - 이미지 또는 PDF로 저장, 카톡 공유 가능
  - "왜 이게 1위인지" 한 줄 설명 제공


----------------------------------------
5. 계산 로직 (핵심 알고리즘)
----------------------------------------

(1) 환산시급
    월 근무시간 = 1일 근무시간 × 주 근무일수 × 4.345
    환산시급 = 월급 ÷ 월 근무시간
    ※ 휴게시간이 명시된 경우 근무시간에서 제외

(2) 가족(개인) 시간
    사용자가 "가족이 집에 있는 시간대"를 설정
    → 그 시간대와 내 비근무시간이 겹치는 시간 계산
    → 주말 휴무일은 별도 가산

(3) 시간 조건 충족도
    사용자가 설정한 "가능한 출근시간" 기준으로
    가능 / 빠듯 / 불가 3단계 판정

(4) 종합 점수
    각 기준별 점수(0~100점)를 산출한 뒤,
    사용자가 정한 우선순위 가중치를 곱해서 합산

    예) 1순위 40%, 2순위 30%, 3순위 20%, 4순위 10%


----------------------------------------
6. 개발 단계 (MVP부터 차근차근)
----------------------------------------

■ 1단계 (MVP / 약 2~4주)
  - 웹 프로토타입으로 제작
  - 공고 직접 입력 (항목별)
  - 기준 선택 + 순서 정하기
  - 자동 채점 및 순위 결과 표시
  → 목표: "이게 실제로 쓸모 있는가"를 검증

■ 2단계 (약 2주)
  - 사용자 유형별 우선순위 템플릿 추가
  - 결과 카드 이미지/PDF 저장 기능
  - 입력한 공고 저장 기능

■ 3단계 (약 3~4주)
  - 공고 텍스트 붙여넣기 → 자동 항목 추출
  - 공고 캡처 이미지 업로드 → OCR 자동 인식

■ 4단계
  - 모바일 앱으로 전환 (안드로이드/iOS)
  - 비교 이력 관리, 즐겨찾기
  - (선택) 채용 사이트 연동


----------------------------------------
7. 기술 구성 (제안)
----------------------------------------

■ 1단계 프로토타입
  - 프론트엔드: React 또는 순수 HTML/JS
  - 데이터 저장: 브라우저 로컬 저장 (서버 불필요)
  → 서버 비용 0원으로 검증 가능

■ 3~4단계 확장 시
  - 모바일: React Native / Expo
  - 백엔드: Supabase (무료 티어로 시작 가능)
  - OCR: 공고 이미지 텍스트 인식 API 활용
  - 공고 자동 파싱: AI API 활용

※ 처음부터 서버·DB를 붙이지 말 것.
   1단계는 로컬 저장만으로 충분하며,
   실제 사용자 반응을 본 뒤 확장하는 것이 비용 면에서 유리하다.


----------------------------------------
8. 예상되는 어려움과 대응
----------------------------------------

문제 1. 공고 양식이 제각각이라 자동 추출이 어렵다
  → 1단계는 수동 입력으로 시작
  → 자동 추출은 3단계에서, 실패 시 수동 보정 가능하게

문제 2. "창업비용" 같은 항목은 정확한 데이터가 없다
  → 업종별 통상 시세를 참고값으로 제공
  → 반드시 "추정치"임을 명시할 것

문제 3. 사용자가 기준 설정을 귀찮아한다
  → 유형별 템플릿 버튼으로 3초 안에 시작 가능하게
  → 기본값을 주고, 원하는 사람만 세부 조정하게

문제 4. 점수만 보여주면 신뢰하지 않는다
  → 점수와 함께 반드시 '실제 값'을 같이 보여줄 것
  → "왜 이 순위인지" 근거를 한 줄로 설명


----------------------------------------
9. 성공 여부를 판단할 기준
----------------------------------------

  - 사용자가 공고를 2개 이상 입력하는가
  - 결과를 끝까지 보고 저장/공유하는가
  - 다시 돌아와서 또 사용하는가

이 3가지가 안 나오면 기능을 더 붙일 게 아니라
문제 정의부터 다시 봐야 한다.
