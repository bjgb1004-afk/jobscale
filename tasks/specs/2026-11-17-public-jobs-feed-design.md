# 공공 채용공고 연결 설계 (2026-11-17)

(설계문서는 `docs/`가 아닌 `tasks/`에 둔다 — `docs/`는 GitHub Pages로 배포되는 웹앱 루트라,
여기 두면 설계문서가 사이트에 같이 공개된다.)

## 범위

공공데이터포털의 **행정안전부 한국지역정보개발원_채용정보 조회 서비스**(지방공기업·지방출자출연기관
채용공고, 원본은 클린아이 `job.cleaneye.go.kr`)를 앱에 연결한다.

1. **둘러보기** — 새 탭에서 내 지역 모집중 공고를 마감 임박순으로 본다.
2. **담기** — 공고를 눌러 비교목록에 바로 넣는다. 자동으로 채울 수 있는 칸은 채우고,
   채울 수 없어 추정한 칸은 "확인 필요"로 명시한다.

범위 밖: 알바·시급 공고(이 API에 없다), 공고 알림, 지원 이력 관리.

## 데이터 원본에서 확인한 사실 (2026-11-17 실측)

- `YEARINCOME`은 금액이 아니라 구간 문자열이다: `2600만원 이상`(32건), `1200만원 이하`(16건),
  `1억원 이상`(8건), `무급`(7건) 등.
- `JOB_TYPE` 실측값: 기간제, 일반정규직, 일반계약직, 무기계약직, 전문계약직, 비상임, 인턴.

## 구조 — 왜 "하루 한 번 받아서 파일로"인가

앱은 서버가 없는 정적 사이트(GitHub Pages)다. 브라우저에서 API를 직접 부르면 인증키가 소스에
박힌다. 중계 서버를 세우면 "서버 없음"이라는 이 앱의 성질이 깨진다.
→ **GitHub Actions가 하루 한 번 API를 받아 정적 JSON으로 커밋**하고, 앱은 그 파일만 읽는다.
키는 GitHub Secrets에 남고, 앱은 서버 0대를 유지하며, 서비스워커가 캐시하므로 오프라인에서도 보인다.

**한도 계산**
- GitHub Actions: 리포가 **public**이라 무료 분이 **무제한**이다(무료 2,000분/월 제한은 private 전용).
- 공공데이터 API: 하루 1회 실행 × 시도 약 16~20회 호출 = **하루 최대 20건**.
  개발계정 일반적 한도 10,000건/일 기준 **0.2%**. 월 600건. 한도 걱정 없음.
- 수동 재실행(`workflow_dispatch`)을 하루 10번 해도 200건 → 2%.

## 1. 수집 — `scripts/fetchJobs.mjs` (신규)

Node 기본 기능만 쓴다. **설치할 패키지 0개** (XML은 항목 구조가 평평하고 중첩/속성/CDATA가 없어
정규식 추출로 충분하다. `&amp; &lt; &gt; &quot; &#39;` 5개만 디코딩한다).

흐름: 시도 코드 훑기 → `<item>` 블록 분해 → 필요한 칸만 추출 → 거르기 → `docs/data/jobs.json` 저장.

**거르는 규칙**: `STATUS !== '모집중'` 제외, `PUB_END_DATE`가 오늘 이전이면 제외.

**출력 형식**
```json
{
  "updated": "2026-11-17",
  "source": "행정안전부 한국지역정보개발원_채용정보 조회 서비스 (공공데이터포털)",
  "regions": { "007001": "서울특별시", "007002": "부산광역시" },
  "items": [{
    "id": "81013",
    "sido": "007015",
    "org": "창원시설공단",
    "title": "시민생활체육관 수영소그룹 도급강사 공개모집 공고",
    "field": "이용·숙박·여행·오락·스포츠",
    "jobType": "기간제",
    "emp": "contract",
    "income": "2600만원 이상",
    "incomeWon": 26000000,
    "incomeBound": "min",
    "end": "2026-11-20",
    "addr": "경상남도 창원시 성산구 원이대로 450",
    "url": "https://job.cleaneye.go.kr/user/ypCareersData.do?idx=81013"
  }]
}
```
버리는 칸: 첨부파일명 4종, 자격증 4종, 심사방법, 지역인재 관련, 공고 본문 등. 안 쓴다.
예상 크기 389건 × 약 230바이트 ≈ **90KB**(Pages가 gzip으로 보내면 약 25KB).

**연봉 구간 파싱** (`parseIncome`)
| 입력 | incomeWon | incomeBound |
|---|---|---|
| `2600만원 이상` | 26000000 | `min` |
| `1200만원 이하` | 12000000 | `max` |
| `1억원 이상` | 100000000 | `min` |
| `무급` | 0 | `none` |
| 그 외/빈값 | null | `none` |

**고용형태 매핑** (`mapEmploymentType`) — 앱의 `EMPLOYMENT_TYPES = regular / contract / daily`에 맞춘다.
- `일반정규직`, `무기계약직` → `regular`
- `기간제`, `일반계약직`, `전문계약직`, `인턴`, `비상임` → `contract`
- 모르는 값 → `contract` (score.js의 기본 폴백과 동일)

## 2. 자동 실행 — `.github/workflows/fetch-jobs.yml` (신규)

- `schedule: cron '0 20 * * *'` (UTC 20:00 = 한국 새벽 5시) + `workflow_dispatch`(수동 실행용)
- `permissions: contents: write`
- Node 20 → `node scripts/fetchJobs.mjs` → `git diff --quiet docs/data/jobs.json || (add; commit; push)`
  **내용이 바뀐 날만 커밋한다.** 안 그러면 매일 빈 커밋이 쌓인다.
- 인증키는 `secrets.DATA_GO_KR_KEY`로 주입. `key.txt`는 계속 `.gitignore` 대상.
- API가 죽거나 응답이 비면 **기존 파일을 덮어쓰지 않고 실패로 끝낸다**(어제 데이터가 빈 목록보다 낫다).

## 3. 둘러보기 탭 (앱)

- 네비에 탭 추가. 첫 진입 시 시도 선택을 요구하고, 고른 값은 localStorage에 기억한다(`feedSido`).
- 목록은 **마감 임박순**(`end` 오름차순). 각 카드:
  공고제목 / 기관명 / 고용형태 / 연봉 구간 원문 / `D-3` / [원문 보기] [비교에 담기]
- 렌더 시점에도 마감 지난 건 숨긴다(JSON이 최대 하루 묵을 수 있으므로).
- 목록 하단 고정 문구: **"자료 제공: 행정안전부 한국지역정보개발원(공공데이터포털)"** +
  `updated` 날짜. 공공데이터는 **출처 표시가 이용 조건**이라 선택이 아니다.
- `jobs.json`을 못 읽으면(최초 방문 + 오프라인) "목록을 불러오지 못했습니다" 안내만 띄운다.

## 4. 담기 (앱)

`saveJobForm()`이 만드는 것과 **같은 모양의 job 객체**를 만들어 `state.jobs`에 넣는다.
등록폼을 거치지 않으므로, 폼이 보장하던 유효성을 여기서 직접 지켜야 한다.

| job 필드 | 값 | 출처 |
|---|---|---|
| `name` | `기관명 · 공고제목`, 40자로 자름(폼의 maxlength와 동일) | 공고 |
| `pay.unit` | `'monthly'` | 고정 |
| `pay.amount` | `round(incomeWon / 12 / 10000)` — **월급 만원 단위** | 공고(환산) |
| `employmentType` | 매핑 결과 | 공고 |
| `sourceUrl` | 공고 원문 URL | 공고 |
| `start` / `end` | `'09:00'` / `'18:00'` | **추정** |
| `breakMin` | `60` | **추정** |
| `daysPerWeek` | `5` | **추정** |
| `commuteMin` | `0` | **추정** |
| `intensity` | 기존 기본값 | **추정** |
| `insurance` | `false` | 추정하지 않음(공공기관이라도 공고에 명시 없음) |
| `weekendWork` | `false` | 추정하지 않음 |
| `needsCheck` | `['pay', 'hours']` | 신규 필드 |

**왜 시간을 비워두지 않는가**: `score.js`의 `monthlyWorkHours()`는 `퇴근 - 출근 <= 0`이면
야간 교대로 보고 24시간을 더한다. 시간을 빈칸으로 넣으면 **하루 24시간 근무로 계산**되어
실질시급이 바닥나고 순위가 망가진다. 폼이 출근·퇴근·통근을 필수로 받는 이유도 같다.
담기도 같은 불변식을 지켜 유효한 job만 만든다. (`score.js`는 건드리지 않는다.)

**추정값을 숨기지 않는다**
- 순위 카드에 `확인 필요` 배지. 누르면 그 공고의 수정 화면으로 간다.
- 배지 설명: "근무시간·통근은 공고에 없어 표준값(09–18시, 주5일)으로 넣었습니다. 고쳐야 실질시급이 맞습니다."
- 급여 옆: `incomeBound === 'min'`이면 "공고 기준 최소값", `'max'`면 "공고 기준 최대값".
- `incomeWon === 0`(무급)이면 담기 버튼 대신 "무급 공고" 표시만 한다.
- `incomeWon === null`(연봉 칸이 비었거나 형식을 모르는 경우)이면 담되 `pay.amount = 0`으로 넣고
  배지를 "급여 미기재 — 직접 입력 필요"로 바꾼다. `NaN`이 job에 들어가면 점수 계산 전체가 깨진다.
- 이미 담은 공고(`sourceUrl`이 같은 job이 있음)는 버튼이 `담김`으로 바뀌고 다시 눌리지 않는다.

**기존 기능 영향**: `needsCheck`가 job 객체에 추가되므로 JSON 백업/복원과 URL 공유에 같이 실려야 한다.
둘 다 job 객체를 통째로 직렬화하므로 그대로 통과하지만, 복원·공유 왕복 테스트로 확인한다.

## 7. 스토어 제출과의 순서

이 앱은 TWA라 **설치된 앱이 여는 화면 = 이 웹페이지**다. 배포하면 심사관이 보는 화면도 같이 바뀐다.
AAB는 원격 URL을 열 뿐이라 **재빌드는 필요 없다**. 순서:
**기능 완성 → Pages 배포 → 스크린샷/스토어 설명에 이 기능 반영 → 그 다음 AAB 업로드·제출.**
