가능합니다. 다만 **“채용공고를 자동으로 긁어와서 AI가 평가해주는 앱”**으로 만들면 개발비·유지비·데이터 이용약관 문제가 커집니다.

현실적인 방향은 **사용자가 채용공고 정보를 입력하거나 복사해 넣으면, 사용자가 정한 우선순위에 따라 객관적인 점수를 계산해주는 앱**입니다. 초기 MVP는 서버·AI 없이도 충분히 만들 수 있습니다.

# 구직자 맞춤 채용공고 비교 앱 개발계획서

## 1. 서비스 한 줄 정의

> **“나에게 중요한 조건을 정하면, 여러 채용공고를 내 기준으로 점수화하고 순위를 보여주는 앱”**

단순한 채용정보 앱이 아니라 **채용공고 의사결정 도구**입니다.

예를 들어:

**A회사**

* 월급 280만원
* 09:00~18:00
* 집에서 35분
* 주 5일
* 육체노동 보통

**B회사**

* 월급 250만원
* 08:00~16:00
* 집에서 10분
* 주 5일
* 육체노동 낮음

사용자가

> 급여 40%
> 출퇴근 25%
> 근무시간 20%
> 업무강도 15%

로 설정하면 앱이 자동으로 계산합니다.

**A회사 78점**
**B회사 84점 → 1위**

즉, **“누구에게나 좋은 직장”이 아니라 “나에게 좋은 직장”을 찾는 것**이 핵심입니다.

# 2. 해결하려는 문제

현재 구직자는 채용공고를 여러 개 보면 다음 정보를 따로 비교해야 합니다.

* 급여
* 근무시간
* 근무일수
* 휴게시간
* 출퇴근 거리
* 업무강도
* 고용형태
* 복지
* 주말근무
* 야간근무
* 경력 요구
* 실제 월 근무시간

문제는 단순히 정보가 많은 것이 아닙니다.

### 사람마다 중요도가 다릅니다.

예를 들어:

**A 사용자**

> 월급이 가장 중요

**B 사용자**

> 오후 4시 이전 퇴근이 가장 중요

**C 사용자**

> 집에서 가까운 것이 가장 중요

**D 사용자**

> 육체적으로 편한 일이 가장 중요

따라서 기존 채용 플랫폼의 단순한 **급여순 / 거리순 / 최신순 정렬**만으로는 개인의 실제 의사결정을 충분히 지원하지 못합니다.

# 3. 핵심 서비스 구조

전체 흐름은 매우 단순하게 만듭니다.

```text
① 내가 중요하게 생각하는 조건 설정
                ↓
② 채용공고 등록
                ↓
③ 조건별 점수 자동 계산
                ↓
④ 종합점수 계산
                ↓
⑤ 채용공고 순위 비교
                ↓
⑥ 상세 비교
```

# 4. MVP에서 반드시 들어갈 기능

## ① 사용자 우선순위 설정

처음부터 복잡한 설문을 만들지 않습니다.

사용자가 다음 항목의 중요도를 정합니다.

### 기본 평가항목

* 급여
* 근무시간
* 근무일수
* 출퇴근 시간
* 업무강도
* 휴일
* 고용형태
* 복지
* 경력/자격요건

예:

| 항목   |   중요도 |
| ---- | ----: |
| 급여   | ★★★★★ |
| 출퇴근  |  ★★★★ |
| 근무시간 |  ★★★★ |
| 업무강도 |   ★★★ |
| 휴일   |   ★★★ |
| 복지   |    ★★ |

앱 내부에서는 이것을 **가중치**로 변환합니다.

예:

```text
급여       30%
출퇴근     20%
근무시간   20%
업무강도   15%
휴일       10%
복지        5%
```

사용자는 숫자를 직접 입력하지 않아도 됩니다.

**별 1~5개 선택 방식**이 훨씬 쉽습니다.

# 7. 점수 계산 엔진

이 앱의 핵심입니다.

단순히 모든 항목을 더하는 방식이 아니라 **정규화 + 가중치** 방식을 사용합니다.

예를 들어 급여가 높을수록 점수가 높게 합니다.

### 급여 점수

예를 들어 비교 대상 중

```text
최저 230만원
최고 320만원
```

이라면 각 공고를 상대적으로 계산할 수 있습니다.

다만 이것만 사용하면 문제가 있습니다.

**300만원과 310만원의 차이**와
**230만원과 240만원의 차이**를 동일하게 취급할 수 있기 때문입니다.

따라서 MVP에서는 항목별로 현실적인 점수표를 만드는 것이 더 이해하기 쉽습니다.

예:

### 월급

| 월급       |  점수 |
| -------- | --: |
| 230만원    |  60 |
| 250만원    |  70 |
| 270만원    |  80 |
| 290만원    |  90 |
| 310만원 이상 | 100 |

---

# 8. 근무시간 점수

예:

```text
09:00~18:00 → 80점
08:00~16:00 → 95점
10:00~19:00 → 70점
```

그런데 사용자의 선호에 따라 달라져야 합니다.

예를 들어 사용자가

> **“오후 5시 전에 끝나는 일이 좋다.”**

라고 선택했다면

```text
16:00 퇴근 → 100
17:00 퇴근 → 90
18:00 퇴근 → 70
19:00 퇴근 → 50
```

처럼 계산합니다.

# 9. 출퇴근 점수

사용자가 직접 이동시간을 입력합니다.

예:

|   편도시간 |  점수 |
| -----: | --: |
|    10분 | 100 |
|    20분 |  90 |
|    30분 |  80 |
|    40분 |  70 |
|    60분 |  50 |
| 90분 이상 |  20 |

여기에 중요한 기능을 하나 넣습니다.

### 출퇴근 시간 → 월간 시간 손실 계산

예를 들어:

```text
왕복 2시간
주 5일
월 22일
```

이면

**월 44시간을 출퇴근에 사용**

합니다.

앱에서

> “이 직장은 월급은 높지만 출퇴근에 월 44시간을 사용합니다.”

라고 보여주면 단순 점수보다 훨씬 유용합니다.

# 10. 업무강도

업무강도는 자동으로 판단하지 않는 것이 좋습니다.

채용공고만 보고

> “이 일은 힘듭니다.”

라고 앱이 단정하면 오류가 많습니다.

따라서 사용자가 직접 선택합니다.

```text
업무강도

○ 매우 편함
○ 편함
○ 보통
○ 힘듦
○ 매우 힘듦
```

또는

```text
업무강도 ★☆☆☆☆
```

# 11. 최종 점수

예를 들어 사용자의 가중치가:

```text
급여       35%
근무시간   25%
출퇴근     20%
업무강도   15%
복지        5%
```

이고 A사의 항목별 점수가

```text
급여       90
근무시간   70
출퇴근     60
업무강도   80
복지       70
```

이면

```text
90 × 0.35
+ 70 × 0.25
+ 60 × 0.20
+ 80 × 0.15
+ 70 × 0.05
= 76.5점
```

따라서

# A회사

### 종합 76.5점

으로 표시합니다.

# 12. 단순 점수만 보여주면 안 됨

이 앱에서 중요한 UX입니다.

예:

### 🥇 A회사

**87점**

```text
급여       95점
출퇴근     90점
근무시간   85점
업무강도   75점
복지       60점
```

그리고

> **당신의 기준에서 급여와 출퇴근 조건이 좋아 높은 점수를 받았습니다.**

라고 보여줍니다.

반대로 2위는

### B회사

**81점**

> 급여는 A회사보다 낮지만 근무시간과 업무강도에서 높은 점수를 받았습니다.

이렇게 하면 사용자가 **왜 순위가 이렇게 나왔는지** 바로 이해할 수 있습니다.

# 13. 가장 중요한 기능: 가중치 변경 시 즉시 재정렬

이것이 앱의 핵심 재미입니다.

예를 들어 현재:

```text
💰 돈       40%
⏰ 시간     30%
🚗 거리     20%
💪 업무     10%
```

인데 사용자가

> “이번에는 돈보다 가까운 곳이 중요해.”

라고 변경하면

```text
💰 돈       20%
⏰ 시간     25%
🚗 거리     40%
💪 업무     15%
```

순간적으로 순위가 바뀝니다.

```text
기존

1위 A회사 89점
2위 B회사 83점
3위 C회사 77점


변경 후

1위 C회사 91점
2위 B회사 86점
3위 A회사 78점
```

**이 기능이 앱의 핵심 차별점입니다.**

# 14. “조건 제외” 기능

가중치만으로는 부족합니다.

사용자에게는 **절대 양보할 수 없는 조건**이 있기 때문입니다.

예:

```text
❌ 월급 250만원 미만
❌ 오후 6시 이후 퇴근
❌ 주 6일
❌ 편도 60분 이상
```

이런 조건을 설정하면

### A회사

300만원 / 18:00 / 주5일

→ 통과

### B회사

270만원 / 19:00 / 주5일

→ **탈락**

이 기능은 실제 구직 상황에서 상당히 중요합니다.

# 17. 데이터 저장 방식

사용자의 기존 앱 개발 방향과 마찬가지로 **초기에는 서버를 없애는 것**을 권합니다.

```text
React Native / Expo
        ↓
SQLite
        ↓
휴대폰 내부 저장
```

사용자의 채용공고와 평가기준은 휴대폰에 저장합니다.

### 장점

* 서버 비용 0원에 가까움
* Supabase 불필요
* 로그인 불필요
* 개인정보 서버 저장 없음
* 인터넷 없이도 사용 가능
* 유지보수 감소

특히 이 앱은 **채용공고 자체를 사용자가 입력하는 구조**이기 때문에 서버가 없어도 서비스가 성립합니다.

```text
회사명 → ○○마트
급여 → 280만원
근무일 → 5일
근무시간 → 09~18
```

을 자동으로 추출합니다.

이 기능은 AI 없이도 일정한 형식의 텍스트라면 **규칙 기반 파싱**으로 상당 부분 처리할 수 있습니다.

그 다음 복잡한 공고에 한해 AI를 붙이는 방향이 좋습니다.

---

# 20. 채용사이트 자동 수집은 후순위

처음부터

> 사람인 + 잡코리아 + 알바몬 + 워크넷 등의 공고를 자동 수집

하려고 하면 프로젝트가 갑자기 복잡해집니다.

문제가 생기는 부분:

* API 제공 여부
* 이용약관
* 크롤링 제한
* 데이터 재배포 문제
* 서버 필요
* 지속적인 크롤러 유지보수

따라서 MVP는

**“채용공고 플랫폼”이 아니라 “채용공고 비교 계산기”**

로 포지셔닝하는 것이 훨씬 현실적입니다.

---

# 21. 차별화 포인트

기존 채용 플랫폼과 경쟁하면 안 됩니다.

### 기존 서비스

> 어떤 일자리가 있는가?

### 이 앱

> **그중 어떤 일이 나에게 가장 좋은가?**

입니다.

즉,

```text
채용공고 검색
       ↓
기존 채용 플랫폼

채용공고 비교/의사결정
       ↓
이 앱
```

으로 포지션을 분리합니다.

# 22. 특히 좋은 타깃

초기에는 모든 구직자를 대상으로 하기보다 **조건 비교가 중요한 사람**을 노리는 것이 좋습니다.

예:

### ① 주부/육아 병행 구직자

### ③ 단기/알바 구직자

```text
시급

거리
근무시간
```

### ④ 이직자

```text

출퇴근
복지
업무강도
```

특히 **알바/중장년/육아 병행 구직**은 MVP 검증에 적합합니다.

# 23. 상당히 좋은 확장 기능: “실질 시급”

이 기능은 넣을 가치가 높습니다.

예를 들어

### A

```text
월급 300만원
월 근무 176시간
출퇴근 44시간
```

### B

```text
월급 270만원
월 근무 176시간
출퇴근 11시간
```

단순 월급만 보면 A가 좋습니다.

하지만 앱이

> **출퇴근 시간을 포함한 시간당 보상**

을 계산하면 비교가 달라질 수 있습니다.

예:

```text
A
300만원 ÷ (176+44)
= 약 13,636원/시간

B
270만원 ÷ (176+11)
= 약 14,439원/시간
```

따라서

> **“월급은 A가 높지만, 내 시간을 기준으로 보면 B가 유리합니다.”**

라는 분석이 가능합니다.

이것이 앱의 상당히 강력한 차별점이 될 수 있습니다.

---

# 24. 단, 점수를 “객관적 직장평가”라고 표현하면 안 됨

중요합니다.

앱이 계산하는 것은

> **“좋은 직장 점수”**

가 아니라

> **“사용자가 설정한 조건에 따른 적합도 점수”**

입니다.

따라서 앱 문구도

❌ 좋은 회사 92점

보다는

✅ **내 기준 적합도 92점**

이 안전하고 정확합니다.

# 29. 이 앱의 가장 중요한 MVP 테스트

앱을 만든 뒤 다운로드 숫자보다 먼저 이것을 테스트해야 합니다.

사용자에게 채용공고 3개를 보여주고:

> **“어느 곳을 선택하시겠어요?”**

라고 합니다.

그 다음 앱에서 동일한 공고를 비교하게 합니다.

그리고

> **“앱의 순위가 본인이 생각한 순위와 비슷했나요?”**

를 확인합니다.

여기서 중요한 것은 AI 정확도가 아닙니다.

**사용자가 자신의 선택을 정리하는 데 실제로 도움이 되는가**입니다.

# 30. 최종 제품 정의

이 앱은 **“채용공고를 찾아주는 앱”으로 만들면 경쟁력이 약합니다.**

반대로 다음과 같이 정의하면 상당히 명확합니다.

> ### 나에게 맞는 직장 계산기
>
> 여러 채용공고를 등록하고
> **내가 중요하게 생각하는 급여·시간·거리·업무강도 등의 비중을 설정하면**
> 각 공고의 **내 기준 적합도와 순위를 자동으로 계산해주는 앱**

그리고 MVP의 핵심은 딱 **세 가지**입니다.

### ① 내 기준 설정

**“나는 무엇을 중요하게 보는가?”**

### ② 공고 비교

**“이 회사는 내 조건에 얼마나 맞는가?”**

### ③ 순위 계산

**“그래서 어디가 나에게 가장 좋은가?”**

이 구조라면 **서버·AI·채용공고 API 없이도 실제 출시 가능한 앱**이 됩니다. 특히 사용자의 기존 개발 방향처럼 **Expo + SQLite + 로컬 계산**으로 시작하면 초기 비용과 유지보수를 매우 낮게 유지할 수 있습니다.
